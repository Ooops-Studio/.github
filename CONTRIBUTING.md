# Contributing to Ooops Design Studio

## Before you begin

- Read the repository README and any local contribution notes before changing code.
- Follow the repository's package, framework, accessibility, security and release boundaries. Do not assume an organization-wide command or toolchain.
- Keep changes focused. Discuss a broad architectural change before implementing it.

## Pull requests

- Use a descriptive branch and commit history.
- Explain what changed, why it changed, and any compatibility or deployment impact.
- Run the repository's required validation commands. Add or update tests for changed behavior.
- Include screenshots or recordings for user-facing changes, and describe manual verification where automated coverage is not practical.
- Update public documentation, changelogs and migration notes when public APIs or setup behavior change.

## Security and accessibility

- Do not commit secrets, private credentials, personal data or production-only configuration.
- Report vulnerabilities privately using the process in [SECURITY.md](SECURITY.md), not through public issues.
- Preserve semantic HTML, keyboard access, focus handling, visible focus states and reduced-motion support in interface changes.

## Help

For general project questions, use the repository's documented support channel or contact [hello@ooops.studio](mailto:hello@ooops.studio).
