# Security Policy

## Supported software

Security fixes are considered for the current maintained release and the default branch of actively maintained repositories. Archived repositories and unsupported historical versions may not receive fixes.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Email [hello@ooops.studio](mailto:hello@ooops.studio) with:

- a clear description of the issue and affected repository or version;
- reproducible steps or a proof of concept where safe to share;
- the potential impact and any suggested mitigation;
- a contact method and disclosure preference.

We aim to acknowledge reports within three business days and will coordinate a remediation and disclosure timeline with the reporter. Credit is optional and provided only with permission.

## Scope

Report vulnerabilities involving authentication, authorization, data exposure, injection, cross-site scripting, cross-site request forgery, remote code execution, dependency compromise or material availability risk. Please avoid testing that could disrupt production systems or access data that is not yours.
